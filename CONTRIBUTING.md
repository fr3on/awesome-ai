# Contributing

Thanks for considering a contribution. This list stays useful by staying selective, so please read this before opening a PR.

## Before you submit

Check that your addition:

- [ ] Is actively maintained (a commit or release within the last ~12 months, or is a stable/finished paper or standard)
- [ ] Has clear documentation or a landing page a newcomer can act on
- [ ] Isn't already in the list (search the README first)
- [ ] Fits an existing category, or justifies a new one
- [ ] Includes a one-line description that says what makes it useful or different, not just what it is

## How to submit

1. Fork the repo and create a branch.
2. Add your entry in alphabetical-ish order within its category, matching the existing format:

   ```markdown
   - [Name](https://link) - One sentence on what it does and why it's worth including.
   ```

3. Keep the description factual and specific. Avoid marketing language ("revolutionary," "best-in-class," "game-changing").
4. One entry per PR is easiest to review. Multiple related entries in one PR is fine too.
5. Open the PR with a short note on why the entry belongs.

## What gets rejected

- Abandoned or archived projects
- Entries with no working link or documentation
- Vague descriptions that just restate the name
- Self-promotional entries without independent traction (some usage, stars, or adoption beyond the submitter's own project)
- Duplicate categories or entries

## Adding a new category

Open an issue first if you think a whole new section is missing (e.g. a domain the list doesn't cover yet). That way we can agree on scope before a PR shows up with entries for a category that might not fit.
